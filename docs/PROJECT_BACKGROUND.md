# 项目背景与决策记录

记录日期：2026-11-12。当前交付版本：Pocket Shelf 1.2.0。

本文保存本项目从手机模拟器配置演变为下载工具的背景，便于后续接手。当前使用方法、构建命令和验证记录以 [README](../README.md) 为入口；版本与实际行为还应核对 Manifest、源码和验证产物。

## 1. 最初要解决的问题

用户通过电脑连接自己的安卓手机，并购买了蓝牙手柄，希望在手机上方便地玩复古主机游戏。最初关注 PS2、GBA、3DS，后来明确增加 FC、SFC 和世嘉平台。

用户希望尽可能采用开源方案，减少分散的软件、权限提示和目录配置。理想体验是：统一浏览游戏，点一下就进入游戏，不必经常进入各模拟器自己的设置与游戏菜单；手柄和触屏都应能操作。

测试设备为荣耀 Magic5 Pro / PGT-AN10、Android 16、骁龙 8 Gen 2。设备信息用于说明当时的验证环境，不是对其他安卓设备兼容性的承诺。

## 2. 为什么形成当前方案

| 阶段             | 做过的工作                                                   | 得到的结论                                                     |
| ---------------- | ------------------------------------------------------------ | -------------------------------------------------------------- |
| 独立模拟器       | 安装并配置 RetroArch、Azahar、ARMSX2 等；尝试 PS2 方案       | 软件和设置分散，难以满足统一体验                               |
| Pegasus 前端     | 制作中文游戏大厅主题，尝试直接启动模拟器、返回大厅与触屏控制 | 可以改善大厅交互，但运行和权限仍属于多个独立应用               |
| Omnidroid        | 选择内嵌模拟器内核的开源整合应用；当时安装 2.6.5             | 由现成项目承担模拟运行、内核和游戏内设置，避免自行重做模拟器   |
| Pocket Shelf 1.0 | 用户要求开发小工具，浏览 Megathread 资源并下载到平台目录     | 跑通目录、下载、导入与直启，但来源过多，能列出名字不等于能下载 |
| Pocket Shelf 1.1 | 用户要求简洁、大气、避免幼稚；修复滚动并优化竖屏             | 确立中性深灰界面、独立滚动区域和竖屏底部导航                   |
| Pocket Shelf 1.2 | 用户指出登录来源可用性差，希望尽量只放直接下载的内容         | 默认收敛到两个免登录 HTTPS 提供方，并在下载前检测真实文件      |

用户后来明确要求卸载先前安装的旧前端与独立模拟器。Pegasus、RetroArch、Azahar、ARMSX2 已卸载，NetherSX2 更早已移除；Omnidroid 与共享游戏文件保留。旧主题是历史方案，不应因看到其目录就默认恢复部署。

## 3. 当前产品定位

**Pocket Shelf 是 Omnidroid 的游戏获取与导入工具，模拟运行由 Omnidroid 完成。**

当前实际采用两个应用配合的方式：Pocket Shelf 浏览、检测、下载和管理文件；Omnidroid 负责运行。这是用户后续提出“开发一个小工具配合 Omnidroid”后形成的方案，尚未实现最初设想的全部功能合并为一个 APK。

主要流程：

```text
选择平台 → 搜索游戏 → 检测文件直链 → 下载
                                      ↓
                                ROMs/对应平台
                                      ↓
                              调用 Omnidroid 开玩
```

Omnidroid 的内核已经集成在其自身架构中，Pocket Shelf 没有再次打包这些内核，也不负责替换它们。

## 4. 已明确的用户偏好

- **操作少、配置集中。** 共用一个 ROMs 根目录，一次授权后按平台归类，减少反复选目录与权限提示。
- **游戏入口优先。** 直接浏览、下载和启动游戏，减少跳转到其他应用的菜单。
- **界面成熟、克制。** 采用中性深灰、清晰文字和紧凑卡片；已移除卡通掌机、大宣传标语、荧光色和过多装饰。
- **横竖屏都可用。** 横屏侧栏保留文字标签，竖屏用底部导航与两列平台卡片。导航手势不能带动内容区滚动，底栏不能遮住列表末尾。
- **可下载优先于来源数量。** 用户不希望面对大量最终要求登录、跳转网页或无法下载的入口。默认只展示已接入的免登录直链来源。
- **开源与可维护。** 优先使用开源组件；Pocket Shelf 源码以 GPL-3.0-only 提供，相关组件许可随项目保留。

## 5. 当前架构与关键约定

| 部分       | 当前实现                                                                   |
| ---------- | -------------------------------------------------------------------------- |
| 安卓应用   | `dev.pocket.shelf`；Java 原生 Activity、下载服务与文件操作                 |
| 界面       | `assets/index.html`、`style.css`、`app.js`；在本地 WebView 中运行          |
| 界面地址   | `https://app.pocket.local/` 是本地资源映射，不是需要部署的远程网站         |
| 目录数据   | `assets/direct.json`；由 `scripts/refresh-direct.py` 生成                  |
| 目录解析   | `assets/catalog.js`；与来源筛选测试共用                                    |
| 游戏目录   | 手机共享存储中的 `ROMs`，通过 Android SAF 持久授权                         |
| 平台子目录 | FC → `nes`，SFC → `snes`，GBA → `gba`，世嘉 MD → `md`；其余见代码与 README |
| 游戏直启   | 显式调用 Omnidroid 的 `ExternalGameLauncherActivity`，传入获授权的文件 URI |
| 游戏库刷新 | 工具可直接启动新文件；Omnidroid 自己的大厅仍需重新扫描目录                 |
| 下载通知   | 用于前台下载进度；只询问一次，拒绝不阻止在任务页查看状态                   |
| 旧 BT 能力 | 为既有任务续传保留，不再作为默认资源入口                                   |

没有采用网页框架服务端或另建远程后台。工作区起初没有 Android 工程，因此使用现有 Android SDK 工具直接编译和签名；JDK、SDK、构建依赖与检查方式见 README。正常交付 APK 关闭调试，个人安装包没有发布到应用商店。

来源网页只作为数据解析，不执行其脚本；原生 bridge 仅供本地界面使用。目录授权、通知和文件访问遵守 Android 正常流程，不通过绕过权限来制造“已整合”的效果。

## 6. 为什么默认只留两个来源

早期直接接入 Megathread 的 37 个分类页，包含 Archive、Minerva、整包与各种网页入口。用户实际使用后指出：来源太多，部分项目显示“需源站登录”，可用性不足。

1.2 的默认提供方为：

- **Edge Emulation：** 经典游戏主目录。FC、SFC、GBA、MD 等采用免登录 HTTPS 文件直链。
- **Libretro 公共内容：** 公共游戏与演示的补充来源，和经典主目录分开标明，避免混淆内容类型。

登录限制、BT 目录、整包入口、未知平台映射和只会跳转的来源不再出现在默认下载目录中。3DS、PS2 尚未收录本次筛选通过的直链来源，因此没有显示在默认下载平台中；这与 Omnidroid 能否模拟该平台是两回事。

具体文件在下载前进行少量实际读取：检查状态码、响应类型和 ZIP / 7z 文件头，拒绝网页、空文件及受限或失效链接。确认失败的链接会隐藏；网络超时保留重试。成功检查短时缓存，来源检测按钮只抽查样本。

**抽样通过、目录中存在和文件此刻可下载应始终区分。** 不把目录条目数量说成独立游戏数量，也不把平台支持说成每一款游戏均已验证。当前快照、缓存时长与刷新机制见 README。

## 7. 已验证和仍未验证的范围

当前已有以下证据，详细结果位于项目的 `dist/verification/`：

- 1.2 在手机上通过原生检测读取 FC、SFC、GBA、MD 四个不同直链文件的真实文件头与大小；网页 URL 被拒绝。
- 1.2 从新主源下载 FC 自制游戏 Nim & Nom，自动导入 `ROMs/nes`，成功进入 Omnidroid 游戏运行页。
- 浏览器测试覆盖四种尺寸、来源筛选、下载前检测、失败不入队、隐藏失效条目和超时重试。
- 1.1 的手机真实触摸测试确认横屏侧栏、竖屏底栏与内容滚动隔离；后续浏览器回归继续覆盖该行为。
- 早期版本验证过 HTTPS 下载、BT 单文件及 SHA-256 校验、暂停后重开继续、连续下载和已有文件保留。

仍需分别验证的内容包括：真实 PS2 / 3DS 游戏及其 BIOS、解密与性能需求，所有平台与所有版本的游戏兼容性，以及完整的实体蓝牙手柄操作流程。不能用一个 GBA 或 FC 游戏启动成功，推断所有平台都能运行。

早期导入的游戏主要是作者公开发布的自制游戏，用于建立链路，不应把它们描述为用户记忆中的全部商业经典。当前经典主目录与公共内容来源在界面中分开标明。

## 8. 接手时的参考位置

项目内：

- `README.md`：当前使用、构建、来源、权限与验证说明。
- `AndroidManifest.xml`：实际包名、版本与权限。
- `assets/`、`src/`：当前运行实现。
- `scripts/refresh-direct.py`：当前来源快照生成器；旧 `refresh-index.py` 是历史工具。
- `tests/`：目录规则、原生文件头边界、界面与真机测试。
- `dist/`：生成的安装包、源码包和验证产物；不代表每个文件均已纳入 Git。

原工作区还有 `android-game-hub/`、`retro-game-library/`、`retired-emulators-backup-2026-11-12/` 等同级目录，分别保存旧前端方案、游戏库备份和旧应用的可读取配置备份。它们不属于 Pocket Shelf 的运行依赖，也不应作为默认源码打包内容。

继续维护时，优先守住现有的目录授权、存档与文件保留、直接启动、成熟界面和滚动隔离。新增来源应先检查真实下载响应，再决定是否放到默认界面。本文记录当前背景与决策，不自动授权新的发布、提交、推送、卸载或数据清理操作。
